# AnyioTaskHandler 线程任务

`run_in_thread()` 与 `run_in_threads()` 使用现有 AnyIO worker thread，不创建独立线程池或事件循环。
Handler 及其 limiter 应在同一个事件循环中使用。

## 超时与取消

| 场景 | 行为 |
| --- | --- |
| `timeout` 为正数 | 单次调用等待超时抛出 `TimeoutError`，不受 `cancellable` 开关影响 |
| `timeout=None`、`0` 或负数 | 不设置本次调用自己的等待期限 |
| `cancellable=False`（默认） | 屏蔽外部 AnyIO `CancelScope` 取消，自己的 timeout 仍然生效 |
| `cancellable=True` | 外部 AnyIO 取消可中断等待，取消继续向上传播 |
| 工作函数抛出普通异常 | 单次调用原样抛出；批量调用在对应位置返回 `None` |
| 已开始的线程在超时或取消后继续运行 | 保留线程额度，直到工作函数实际结束；结果或异常不再交回已离开的调用方 |

单次调用的 timeout 包含等待线程额度和执行工作的时间。批量调用中，每项取得全局并发额度后开始计时，
覆盖该项等待线程额度及执行工作的时间；它不是整个批次的总期限。批量结果保持输入顺序，超时项为 `None`，
其他项继续执行。外部取消不会被转换成正常的部分结果列表。

`cancellable=False` 的屏蔽范围仅针对 AnyIO 取消域。离开屏蔽范围后，外部取消仍可在后续检查点生效；
直接调用 `asyncio.Task.cancel()` 不受 AnyIO 屏蔽语义保证。

## 线程生命周期与资源

Python 无法通过上述 API 强杀正在运行的线程。超时表示调用方停止等待，不表示网络请求、文件写入或其他
同步副作用已经停止。同步 SDK 仍需配置自己的连接、读写或 RPC 超时；需要停止长计算时，工作函数应实现
协作取消。

实际工作仍在运行时不会归还 Handler 的线程额度，后续任务继续排队，避免反复超时导致并发数失控。
已经等待超时、但尚未开始执行的工作不会在稍后执行。

`shutdown()` 取消并等待 Handler 所属的后台协程，不强制终止或等待已被调用方放弃的线程。
调用方必须安排仍被工作线程使用的文件、客户端等资源的生命周期，不能在捕获 `TimeoutError` 后立即关闭
这些资源并假设工作已经结束。

上述规则只调整 Handler 的线程任务接口。基础 `anyio_run_in_thread()` 保持原来的 AnyIO 参数语义；
子进程是否可终止仍由 `run_in_process()` 的 `cancellable` 参数控制，其超时策略未在此次调整中改变。
